# 网上商城系统 — 进阶部署与优化指南

本文档列出从课设项目到生产可用的电子商务系统所需补充的设计与实现，按优先级划分为三个梯队。

---

## 第一梯队：安全（上线前必须解决）

### 1.1 SQL 注入防护

当前状态：MyBatis-Plus 参数化查询已覆盖大部分场景，但 `ProductMapper.selectHotProducts` 使用 `LIMIT #{limit}` 是安全的（参数化）。需排查是否有人为拼接 SQL。

建议：
- 全面禁用 `${}` 占位符，统一使用 `#{}`
- 对 `orderBy` 等动态排序字段做白名单校验，禁止前端直接传列名

### 1.2 HTTPS 强制

- 申请免费 SSL 证书（Let's Encrypt / 阿里云免费证书）
- Nginx 配置 80→443 强制跳转
- 后端 `application.yml` 开启 `server.ssl` 或交由 Nginx 处理

### 1.3 JWT 安全增强

| 当前 | 建议 |
|---|---|
| 密钥硬编码在 `application.yml` | 环境变量或密钥管理服务 |
| 无刷新机制 | 短期 AccessToken(15min) + 长期 RefreshToken(7d) |
| 无登出失效 | Redis 黑名单或 Token 版本号 |
| 密钥是 Base64 短字符串 | 至少 256 位随机密钥 |

### 1.4 密码策略

- 注册时强制密码复杂度：8 位以上，含大小写字母+数字
- 登录失败 5 次锁定账号 15 分钟
- 密码定期过期提醒（90 天）

### 1.5 XSS 与 CSRF 防护

- 前端输出统一做 HTML 实体转义（Vue 默认已处理 `{{ }}`）
- 商品描述等富文本字段需 DOMPurify 清洗
- 关键操作（支付、修改密码）加 CSRF Token 或 SameSite Cookie
- 文件上传校验 MIME 类型 + 文件魔术字，防 webshell 上传

### 1.6 CORS 收紧

当前 `allowedOriginPatterns: "*"` 允许任意来源。上线改为：

```yaml
allowed-origins: "https://your-domain.com"
```

### 1.7 敏感信息脱敏

- 日志中不打印 Token、密码
- 接口返回不泄露异常堆栈（当前 GlobalExceptionHandler 已处理）
- `application.yml` 不提交到 Git（当前已在 .gitignore 之外？）

## 第二梯队：可靠性与性能

### 2.1 数据库优化

| 问题 | 方案 |
|---|---|
| 商品搜索 `LIKE '%keyword%'` 全表扫描 | MySQL 全文索引或 Elasticsearch |
| 分类树每次查询加载全表 | Redis 缓存分类树 |
| 热销商品无索引 | `products(sales, status)` 联合索引 |
| 订单表无复合索引 | `orders(user_id, status, created_at)` 联合索引 |
| 分页深度翻页性能差 | 游标分页或 ES 的 `search_after` |

### 2.2 缓存策略

```
热点数据缓存层级:
├── 浏览器缓存: 商品图片 (Cache-Control: max-age=604800)
├── CDN 缓存: 静态资源 (/uploads/*)
├── Nginx 缓存: 商品列表页 GET 请求 (proxy_cache)
└── Redis 缓存: 分类树、热销商品、用户 Session
```

建议引入 Spring Cache (`@Cacheable`) + Redis：
- 商品详情：缓存 5 分钟，更新/下架时主动失效
- 分类树：缓存 1 小时，CRUD 后失效（当前已有 60s 内存缓存）
- 热销商品：缓存 10 分钟

### 2.3 图片优化

| 当前 | 改进 |
|---|---|
| 原图上传，无压缩 | 上传时生成多尺寸缩略图（200px/400px/800px） |
| 无格式转换 | WebP 格式 + JPEG 兜底 |
| 本地磁盘存储 | 对象存储 OSS/MinIO，CDN 加速 |
| 无懒加载 | 列表页图片 `loading="lazy"`（当前 el-image 已支持） |

### 2.4 限流与防刷

- 登录接口：同一 IP 每分钟最多 10 次
- 下单接口：同一用户每分钟最多 5 次
- 图片上传：单用户每日 50 张上限
- 引入 RateLimiter（Guava）或 Sentinel

### 2.5 并发控制

- 下单时库存扣减已用乐观锁 `WHERE stock >= ?`，但未处理失败重试
- 建议：扣减失败时重试 3 次，仍失败返回"下单人数过多，请重试"
- 订单号生成加分布式锁或数据库唯一约束兜底

## 第三梯队：业务完善

### 3.1 真实支付接入

当前"模拟支付"需替换为真实支付：

```
支付宝/微信支付流程:
1. 前端请求后端创建支付单
2. 后端调用支付 API 获取二维码/支付链接
3. 用户扫码支付
4. 支付平台异步通知后端 (回调接口需幂等处理)
5. 后端更新订单状态 → PAID
```

回调接口需注意：签名验证、幂等性（`order_no` 去重）、重复通知处理

### 3.2 用户体系增强

| 功能 | 说明 |
|---|---|
| 邮箱验证 | 注册后发送验证链接，激活后可使用 |
| 手机验证 | 短信验证码登录/找回密码 |
| OAuth2 登录 | 微信/支付宝快捷登录 |
| 收货地址管理 | 独立地址表，下单时选择而非每次填写 |
| 用户等级 | 根据消费金额划分等级，不同折扣 |

### 3.3 售后体系

- 退款/退货流程：用户申请 → 商家审核 → 退货物流 → 确认退款
- 退款需对接支付平台退款接口
- 订单状态扩展：新增 `REFUNDING`、`REFUNDED` 状态

### 3.4 库存管理增强

- 库存预警：低于阈值时通知管理员
- SKU 管理：同一商品多规格（颜色/尺寸），独立库存
- 库存流水表：记录每次变更（下单扣减、退货回加、手动调整）

## 第四梯队：基础设施与运维

### 4.1 容器化部署

```dockerfile
# 后端 Dockerfile
FROM openjdk:17-slim
COPY target/shop-1.0.0.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]

# 前端 — 构建后放入 Nginx 镜像
FROM nginx:alpine
COPY dist/ /usr/share/nginx/html/
COPY nginx.conf /etc/nginx/conf.d/default.conf
```

`docker-compose.yml` 编排：MySQL + Redis + Backend + Frontend(Nginx)

### 4.2 Nginx 反向代理

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    # 前端静态文件
    root /usr/share/nginx/html;
    location / { try_files $uri /index.html; }

    # API 代理
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header X-Forwarded-For $remote_addr;
    }

    # 上传文件
    location /uploads/ {
        proxy_pass http://backend:8080;
    }
}
```

### 4.3 CI/CD 流水线

```
Git Push → GitHub Actions:
  1. mvn test (后端单元测试)
  2. npm test (前端测试)
  3. mvn package (构建 jar)
  4. docker build + push
  5. SSH 远程部署 docker-compose up -d
```

### 4.4 监控与告警

| 维度 | 工具 |
|---|---|
| 应用监控 | Spring Boot Actuator + Prometheus + Grafana |
| 日志收集 | ELK (Elasticsearch + Logstash + Kibana) |
| 错误追踪 | Sentry |
| 接口监控 | 健康检查 `/actuator/health`，报警机器人 |
| 业务指标 | 下单量、支付成功率、PV/UV |

### 4.5 数据库备份

- 每日全量备份 + 每小时增量备份
- 备份文件异地存储（OSS/其他机房）
- 定期恢复演练

## 第五梯队：测试与质量

### 5.1 测试体系

```
测试金字塔:
        /\
       /E2E\         Playwright / Cypress — 核心流程 10 条
      /------\
     /集成测试\        Spring Boot Test + Testcontainers — API 全覆盖
    /----------\
   /  单元测试   \      JUnit + Mockito — Service 层覆盖率 > 80%
  /--------------\
```

### 5.2 核心测试用例

- 注册 → 登录 → 浏览 → 加购 → 下单 → 支付 → 确认收货（全流程 E2E）
- 库存不足时下单拒绝
- 并发下单库存不超卖
- 未登录用户访问购物车跳转登录
- 普通用户访问 `/admin` 返回 403

### 5.3 性能测试

- JMeter / k6 压测关键接口
- 目标：商品列表 QPS 1000+，下单 QPS 100+
- 找出瓶颈：慢 SQL → 加索引；热点数据 → 加缓存

## 第六梯队：合规与隐私

### 6.1 数据隐私

- 用户密码 BCrypt 加盐（已实现）
- 手机号、邮箱脱敏展示：`138****8000`
- 提供用户数据导出（JSON 格式）和账号注销功能
- 隐私政策页面 + 用户协议

### 6.2 日志审计

- 关键操作日志：登录、下单、支付、修改密码 → 记录 IP、时间、操作人
- 日志保留 90 天
- 敏感日志字段脱敏

### 6.3 法律合规

- ICP 备案（中国大陆上线必需）
- 增值电信业务许可证（涉及在线交易时）
- GDPR 合规（如有欧盟用户）
