### 1.2 分层说明

| 层 | 职责 | 关键类 |
|---|---|---|
| Controller | 接收 HTTP 请求，参数校验，调用 Service，返回统一响应 | AuthController, ProductController, AdminProductController... |
| Service | 业务逻辑编排，事务管理 | UserServiceImpl, OrderServiceImpl... |
| Mapper | 数据库 CRUD，自定义 SQL | UserMapper, ProductMapper... |
| Entity | 数据库实体映射 | User, Product, Order... |
| DTO | 请求数据传输对象 | LoginRequest, RegisterRequest, OrderCreateRequest... |
| VO | 响应视图对象 | UserVO, ProductVO, OrderVO... |
| Security | 认证与授权 | JwtUtil, AuthInterceptor, AdminInterceptor, UserContext |
| Common | 通用工具与响应 | Result, PageResult, GlobalExceptionHandler |

## 3. 模块设计

### 3.1 认证模块

```
客户端                            服务端
  │                                │
  │  POST /api/auth/register       │
  │  { username, password }        │
  │ ─────────────────────────────→ │
  │                                │ BCrypt 加密 → INSERT users
  │  { code:200, data:{...} }     │
  │ ←───────────────────────────── │
  │                                │
  │  POST /api/auth/login          │
  │  { username, password }        │
  │ ─────────────────────────────→ │
  │                                │ 查用户 → BCrypt 验证
  │                                │ → JWT 签名 { userId, username, role, exp }
  │  { code:200, data:{ token, user } }
  │ ←───────────────────────────── │
  │                                │
  │  后续请求 Header:              │
  │  Authorization: Bearer <token> │
  │ ─────────────────────────────→ │
  │                                │ AuthInterceptor 解析 Token
  │                                │ → UserContext.set(userId, username, role)
  │                                │ → 放行
  │                                │
  │                                │ afterCompletion: UserContext.clear()
```

### 3.2 商品模块

- `GET /api/products` — 支持 `keyword`（LIKE 搜索）、`categoryId`（精确筛选）、`sort`（price_asc/price_desc/sales_desc/newest），默认按销量降序
- `GET /api/products/hot` — 热销 Top N，优先用销售数据，回退按销量降序
- `GET /api/products/search` — 关键词搜索，模糊匹配商品名
- 商品列表返回时 LEFT JOIN 分类名，避免 N+1 查询

### 3.3 购物车模块

- 商品已存在则 `quantity += N`，存在唯一约束防重复
- 购物车项返回时 JOIN 商品表获取实时名称、图片、价格
- 下架商品在购物车列表中过滤并跳过

### 3.4 订单模块

**下单事务（@Transactional）：**

```
1. 校验 cartItemIds 属于当前用户 & selected=1
2. 查询商品，校验在售状态
3. 生成订单号 (yyyyMMddHHmmss + 5位随机)
4. INSERT order + N 条 order_items（快照商品信息）
5. DELETE cart_items（已生成订单的购物车项）
```

**支付（@Transactional）：**

```
1. 校验订单状态 == PENDING & 归属当前用户
2. 逐条扣减库存：UPDATE products SET stock = stock - ? WHERE id = ? AND stock >= ?
3. 检查 affectedRows，为 0 则抛 BusinessException("库存不足")
4. 更新订单状态 → PAID，记录 pay_time
```

### 3.5 后台管理模块

所有 `/api/admin/**` 路径需通过 AdminInterceptor（role == 0）。

**仪表盘统计：**
- 总用户数、总订单数、总商品数
- 总营业额（status >= 1 的订单总金额）
- 各状态订单数

## 4. 安全设计

| 层面 | 措施 |
|---|---|
| 密码存储 | BCrypt 加密（spring-security-crypto） |
| 传输认证 | JWT Token，24h 过期 |
| 接口鉴权 | AuthInterceptor（需登录）+ AdminInterceptor（需管理员） |
| 会话隔离 | ThreadLocal 存储用户上下文，请求结束清除 |
| 库存并发 | 乐观锁 `WHERE stock >= ?` 防超卖 |
| 数据权限 | 订单查询按 userId 隔离，管理员可查看全部 |
| 下单安全 | 校验购物车项归属、商品在售状态 |
