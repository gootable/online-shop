# 网上商城系统 — 需求分析文档

## 1. 引言

### 1.1 项目背景

随着电子商务的普及，B2C 网上商城已成为日常消费的主要渠道。本系统旨在构建一个功能完整的在线购物平台，涵盖用户注册登录、商品浏览与搜索、购物车管理、订单处理以及后台管理等核心业务流程。

### 1.2 项目范围

本系统定位为 B2C 模式的单体电商平台，面向消费者提供商品浏览、搜索、购买的一站式服务，同时为管理员提供商品管理、订单处理、用户管理的后台功能。

### 1.3 用户角色

| 角色 | 说明 | 典型用户 |
|---|---|---|
| 普通用户 | 浏览商品、下单购买的消费者 | 注册用户 |
| 管理员 | 管理系统资源、处理订单 | 商城运营人员 |
| 游客 | 未登录的浏览者 | 潜在用户 |

## 3. 业务流程

### 3.1 用户购物流程

```
[用户登录] → [浏览/搜索商品] → [商品详情] → [加入购物车]
    → [购物车选择商品] → [填写收货信息] → [提交订单]
    → [模拟支付] → [等待发货] → [商家发货] → [确认送达] → [完成]
```

### 3.2 订单状态流转

```
PENDING(待支付) ──支付──→ PAID(已支付) ──发货──→ SHIPPED(已发货) ──送达──→ DELIVERED(已送达) → COMPLETED(已完成)
     │
     └──取消──→ CANCELLED(已取消)
```

- PENDING → PAID：用户模拟支付，扣减商品库存
- PAID → SHIPPED：管理员后台操作发货
- SHIPPED → DELIVERED：管理员确认送达
- PENDING → CANCELLED：用户取消（仅待支付状态可取消）

### 3.3 权限控制流程

```
[请求到达] → 是否为公开路径？──是──→ 放行
                      ↓否
              Authorization Header 提取 Token
                      ↓
              验证 Token 有效性 ──无效──→ 401
                      ↓有效
              将 userId/role 写入 ThreadLocal
                      ↓
              /api/admin/**？──是──→ role == 0？──否──→ 403
                      ↓否                    ↓是
                   放行                    放行
```

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 商品列表查询响应时间 < 500ms |
| 安全 | 密码 BCrypt 加密存储，JWT Token 过期 24h |
| 可用性 | 统一错误处理和提示，空/加载状态覆盖 |
| 可维护性 | 分层架构，前后端分离，代码遵循单一职责 |
| 数据完整性 | 下单事务保证，库存乐观锁防超卖 |

---

## 5. 约束条件

- 单体架构，不使用微服务
- 文件存储使用本地磁盘，不接入 OSS
- 支付为模拟操作，不接入真实支付网关
- 前端开发期间通过 Vite proxy 代理后端请求
